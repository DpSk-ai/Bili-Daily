## 4. 数据导出/恢复能力

### 4.1 覆盖的四个键

| 键 | 内容 |
|---|---|
| `biliDailyRecords` | 观看记录 |
| `biliDailyCandidateImports` | 手动导入候选批次 |
| `biliDailyDiscoveredCandidates` | 页面观察候选 |
| `biliDailyDiscoverySettings` | 自动发现开关与容量设置 |

不导出其他键；不申请新权限；不联网。

### 4.2 导出

- 弹窗底部「数据舱 · 本地备份」→「导出全部数据」。
- 读取 `chrome.storage.local.get([四个已知键])`，由 `data-backup.js` 再挑选四个已知键。
- 生成 JSON：

```json
{
  "format": "bili-daily-backup",
  "version": 1,
  "app": "Bili Daily",
  "appVersion": "1.1",
  "exportedAt": "2026-11-12T...",
  "data": { "biliDailyRecords": { ... }, "...": { ... } }
}
```

- 文件名：`bili-daily-backup-YYYYMMDD-HHMMSS.json`。
- 上限：5 MiB；超过则拒绝并提示。

### 4.3 导入

1. 选择备份 JSON。
2. `parseBackupText` 校验格式、版本、键白名单、危险键、大小。
3. `prepareImport` 调用既有 normalizer：
   - `storage.js` 的 `normalizeRoot`
   - `candidate-store.js` 的 `normalizeStore`
   - `discovered-candidate-store.js` 的 `normalizeStore` / `normalizeSettings`
4. 生成待写 payload，**不写入**。
5. 弹窗显示数量摘要与警告，用户点击「确认恢复」并再次确认。
6. `writePayload` 只写入备份中包含的键；未包含的键保持不变。
7. 写入失败时提示失败；不做自动回滚写入（原始数据未被覆盖）。

### 4.4 安全边界

- 拒绝 `__proto__` / `constructor` / `prototype`（递归检查）。
- 拒绝未知键与非 `bili-daily-backup` v1 格式。
- 拒绝超过 5 MiB 的文本；写入前再次检查 payload 大小。
- 不读取 Cookie、token、页面 HTML。
- 所有预览文本通过 `textContent` 写入。
- 导出前不修改任何存储；导入确认前不写入任何存储。

## 7. 动效与降级

| 动效 | 实现 | 降级 |
|---|---|---|
| 卡片进场 | `cardIn`，透明度 + 6px 上移 | `prefers-reduced-motion` 关闭 |
| 画像条 | `barIn`，`scaleX` | 关闭 |
| 助手全息环 | `ringSpin` / `ringSpinReverse` | 关闭 |
| 状态灯 | `statusBreath` | 关闭 |
| 扫描线 | `scanSweep`（transform） | 关闭 |
| 分隔线光点 | `ruleSweep`（transform） | 关闭 |
| 按钮/卡片悬停 | 150–180ms 过渡 | 关闭 |

- 全部动画只使用 `transform` / `opacity`（CSS 过渡中的 `filter` 仅用于按钮亮度，范围很小）。
- `@media (prefers-reduced-motion: reduce)` 将动画与过渡压到 0.001ms，并显式停止旋转/扫描。
- 助手图片加载失败时显示 CSS 圆形替身 `NEO-01`，布局不塌陷。
- 不引入外部字体、动画库、位图或 CDN。
