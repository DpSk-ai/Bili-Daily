- **阶段**：C1 本地兴趣画像引擎
- **验收日期**：2026-11-11
- **数据来源**：用户本机 Edge 扩展 `chrome.storage.local` 中的 `biliDailyRecords`
- **验收方式**：在扩展页面上下文中只读调用 `buildInterestProfile`，前后各读一次存储快照比对
- **结论**：**通过**（只读性、窗口计算、数据不足降级均符合预期）

## 3. 解读

1. **7 天与 30 天完全一致**：全部记录都落在最近 7 天内，30 天窗口没有额外的历史数据。
   这不是计算错误，而是数据本身如此。
2. **8.9 分钟 / 4 个有效视频**：低于 `insufficient` 的启发式阈值（10 分钟、2 个有效观看日）。
   引擎正确地给出了降级状态，没有把噪声包装成"兴趣画像"。
3. **分区覆盖率 87.3%**：约 12.7% 的观看时长对应的记录缺少可识别分区，被统一归入「未知」桶并计入占比，
   没有被悄悄丢弃。
4. **知识 69.3% / 美食 18.0%**：这是当前 4 个视频构成的分区分布，样本量太小，
   **不能据此判断用户长期兴趣**，也不能用于评价任何排序算法。

## 4. 本次验收证明了什么 / 没证明什么

**证明了**：

- 画像引擎可以在真实 MV3 扩展页面中加载并执行。
- 计算过程是只读的，存储快照前后一致。
- 窗口边界、分区聚合、覆盖率、未知桶、状态降级在真实数据上都按设计工作。

**没有证明**：

- 画像在长期大数据量下的准确性（样本只有 4 个视频）。
- 内存与耗时（数据量过小，测不出有意义的数字）。
- 跨时区 / DST 行为。
- 任何推荐算法（TF-IDF、余弦、MMR、ALS、BPR）的效果 —— C1 未涉及推荐。
